# Game UI

Entity/Component pattern — Unity GameObject UI style. UI elements are ECS entities.

## Why this pattern

- Reuses ECS storage, editor inspector, hot-reload, serialization, animation systems.
- Artists drag UI elements in the same editor viewport they use for gameplay.
- Zero duplication with the rest of the engine.
- Much less to build than Unreal UMG (which is a whole parallel subsystem).

## Components (module: `zues_ui.dll`)

- `UICanvas` — root of a UI tree. Modes: `screen_overlay`, `screen_camera`, `world_space`.
- `UITransform` — anchors + pivot + size + local rotation. Separate from world `Transform`.
- `UIImage` — sprite / 9-slice background. Tint color.
- `UIText` — font, size, color, alignment, wrapping.
- `UIButton` — state machine (normal/hover/pressed/disabled) + click event.
- `UILayoutGroup` — `VBox` / `HBox` / `Grid`. Auto-arranges children.
- `UILayoutElement` — per-child hints: preferred size, min/max, stretch weight.
- `UIScrollView` — clipped, drag-scrollable region.
- `UIInput` — single-line or multiline text entry.
- `UIMask` — clips descendants to a rect or sprite alpha.

## Canvas modes

- **`screen_overlay`** — drawn after game render, in pixel coords. Default for HUD/menus.
- **`screen_camera`** — drawn at a depth; game camera transforms apply. For parallaxed HUD.
- **`world_space`** — canvas has a world transform like any entity. Diegetic UI (floating health bars, in-game monitors).

## Pipeline

In the ECS phases:

1. `ui_input` phase:
   - Walk canvases in draw order (top-most first).
   - Hit-test pointer against `UIButton` / `UIInput` regions.
   - If hit, mark pointer event as consumed; gameplay input systems won't see it.
2. `ui_layout` phase:
   - For each canvas: walk tree, resolve `UILayoutGroup` auto-layouts, write final `rect` on each UI entity.
3. `ui_render` phase (runs after `render`):
   - Walk canvases and their trees in hierarchy order.
   - Issue draw calls through `IRenderer_2D_v1`.

## Authoring

- In the editor: create a `UICanvas` entity. Add child `UIImage` / `UIButton` / `UIText` entities.
- Layout hints edited in the Inspector like any component.
- Hot reload works — change a component, editor reloads project.dll, UI updates.
- Future: a visual "UI mode" in the editor with on-canvas dragging of anchor handles.

## Not in v1

- Rich text (colored spans, inline images, gradients)
- Animations / tweens / transitions (fade, slide)
- Theming via component overlays
- Data binding (reactive text from game state)

Those will come as follow-up UI work once the basics ship.
